# beatrig: design contract (v0)

A reactive engine for agents and artists: music in, deterministic animation keys out. Built for offline-rendered Unreal work
(fulldome and cinematic renders first). Everything is computed **offline, from frame 0, in Python/numpy**, and baked
into plain Sequencer keys. Renders are deterministic under Movie Render Queue, no plugin is needed at render time, and
an AI agent can drive every step over MCP. A local preview page lets a human see and tweak a rig without opening Unreal.

**Hard rules**
1. **Never ahead of the audio** (ITU-R BT.1359). Every op is causal. A frame reads audio
   only up to its own start time, and a hit lands on the first frame at or after its onset. Delays are ≥ 0. No look-ahead
   anywhere, including smoothing.
2. **Eased motion**. Continuous signals are smoothed/slewed. Only trigger envelopes
   may rise instantly (on-beat hits). Keys are written linear, so tangents can't overshoot.
3. **Deterministic.** The same inputs give byte-identical bake output. Seeds are explicit. There is no wall-clock time.
4. **Light machine load.** CPU only. No torch/demucs install in v0 (stems are a later phase, CPU and opt-in). Run heavy
   loops vectorised; a 60-min show must bake in under ~60 s.
5. Clean-room: all code is original.

## Files (all JSON, all hand-editable, all relative paths resolved from the rig file's folder)
- `rig.json`: what drives what (the "motion graph").
- `notes.json`: editable hit timeline per track (the "note sequence"). Generated by `notes init`, then edited.
- `analysis.json` + `analysis.npz`: cache of the audio analysis (bands at 1 ms, onsets, beat grid). Regenerated
  automatically when the audio file's size/mtime or the analysis settings change.
- `bake.json`: output. Per target, per channel, per frame values, plus simplified keys.

## rig.json
```jsonc
{
  "audio": "../audio/show.wav",          // wav/flac; mono or multichannel (downmixed with optional "channel_weights")
  "fps": 30,
  "frames": null,                        // null = length of the audio
  "audio_offset_frames": 0,              // audio frame 0 = sequence frame this
  "tempo": { "bpm": null, "map": [] },   // null = take from analysis; map = [{ "frame": 0, "bpm": 103.4 }] overrides
  "seed": 1,
  "nodes": [                             // evaluated in dependency order; ids are global names ("globals")
    { "id": "kick",   "op": "band", "lo": 40, "hi": 120 },
    { "id": "kickN",  "op": "normalize", "in": "kick", "range_db": 24 },
    { "id": "kickS",  "op": "smooth", "in": "kickN", "attack_ms": 15, "release_ms": 220 },
    { "id": "hits",   "op": "notes", "track": "kick" },            // triggers + velocity from notes.json
    { "id": "pulse",  "op": "envelope", "in": "hits", "shape": "punch", "length_beats": 0.5 },
    { "id": "ring",   "op": "chase", "in": "pulse", "channels": 8, "step_beats": 0.125 },
    { "id": "mix",    "op": "math", "fn": "max", "in": ["ring", "kickS"] }
  ],
  "layers": [                            // optional layers; intensity keyed with eased crossfades
    { "id": "main", "intensity": [ { "frame": 0, "value": 1 }, { "frame": 450, "value": 0, "ease": "in_out", "fade_frames": 30 } ] }
  ],
  "outputs": [
    { "id": "lights", "layer": "main", "signal": "mix",
      "target": { "kind": "light", "actors": ["Light_0", "...", "Light_7"], "property": "intensity" },
      "min": 500, "max": 20000 },        // channel i -> actor i; 1 channel + N actors = "same" mode
    { "id": "glow", "signal": "kickS",
      "target": { "kind": "mpc", "asset": "/Game/VBTest/MPC_VB", "param": "Glow" }, "min": 0.2, "max": 3 }
  ],
  "bake": { "key_tolerance": 0.002 }    // relative RDP tolerance for key simplification
}
```

### Signals
A signal is `float32[channels, frames]`. Values are usually 0..1 (may exceed). A **trigger** is a signal flagged
`kind="trigger"`: it is non-zero only on a hit frame, and the value is the hit velocity (0..1]. Ops that need triggers accept a value
signal by thresholding it (`threshold` op).

### Ops (v0 set; params in brackets have defaults)
Sources
- `band` lo, hi [Hz], [attack_ms 10, release_ms 150], [weights per audio channel]: causal band envelope (sosfilt +
  one-pole follower on a 1 ms grid, sampled at frame start). Raw linear amplitude.
- `loudness` [attack_ms, release_ms]: K-weighted full-band envelope.
- `onsets` in=<band node or band spec> [threshold 0.3, min_gap_ms 80] → trigger: causal spectral-flux peaks;
  the hit frame is the first frame ≥ the onset time.
- `beats` [every 1, offset 0, subdivide 1] → trigger on the verified beat grid (analysis), not a raw tempo tracker.
- `notes` track → trigger (velocity) + per-hit length and envelope from notes.json.
- `lfo` shape (sine|tri|saw_up|saw_down|square|semi_sine) rate_beats | rate_hz, [phase 0], [channels 1, phase_step 0]
- `const` value [channels 1]
Shaping
- `normalize` in, [range_db 24, hi_pct 99.5, lo_pct 10]: dB-scale 0..1 over the whole bake range. This is not a
  look-ahead problem: it only sets a static gain, and timing is unaffected.
- `smooth` in, attack_ms, release_ms: one-pole up/down follower per channel.
- `spring` in, freq_hz [2], damping [0.6]: critically damped to under-damped follower. Causal, eased "inertia".
- `curve` in, gamma [1] | preset (s_curve|ease_in|ease_out).
- `remap` in, in_lo, in_hi, out_lo, out_hi, [clamp true]
- `threshold` in, level [0.5], [cooldown_ms 100] → trigger on rising edge.
- `envelope` in=<trigger>, shape (binary|punch|gloss|razor|rush|adsr|saw_down|custom), [length_beats | length_ms],
  [attack_ms 0, decay_ms, sustain, release_ms], [points for custom: [[t0..1, v], ...]], velocity-scaled; overlapping
  hits take the max. Attack 0 is allowed here only (rule 2).
- `delay` in, ms | beats, [step_ms | step_beats per channel]
- `math` fn (add|mul|max|min|sub|mix) in=[a, b] [, amount]; channel counts broadcast (1 → N).
- `hold` in, ms: peak hold.
Channels (the "flow" family; this is what makes chases and waves)
- `fanout` in, channels
- `chase` in, channels, step_ms | step_beats, [direction 1|-1], [wrap true]: channel i = in delayed by i·step.
- `cycle` in=<trigger>, channels, [order sequential|pingpong|random], [seed]: each hit goes to the next channel.
- `ripple` in, [neighbours 2], [falloff 0.5], [step_ms 40], [ring true]: each channel's hit spreads to neighbours,
  delayed and attenuated.
- `mirror`, `reverse`, `select` (channels list), `merge` (fn max|mean → 1 channel), `shuffle` [seed]: fixed permutation.

### Layers
Each layer has an intensity curve: keyframes with eased transitions (`ease` in_out|in|out|linear, `fade_frames`), evaluated
smoothly. An output in a layer is `min + (value·intensity)·(max-min)`. To switch looks between song sections, give two layers
opposite intensity keys.

## notes.json
```jsonc
{ "bpm_map": [ { "time": 0.0, "bpm": 103.4 } ], "grid_offset": 0.012,   // seconds; from analysis, editable
  "tracks": { "kick": [ { "time": 1.234, "vel": 0.9, "len_beats": 0.5, "shape": "punch" } ] } }
```
Times are in **seconds of audio**, not frames, so changing the fps never moves hits. `notes init --track kick --from onsets:<node>`
fills a track from detected onsets (or `--from beats`). `notes snap --track kick --grid 1/8 [--strength 1]` quantises.
Every editing action the UI offers maps to this file.

## Analysis (cached)
- Bands are computed on demand per (lo, hi, attack, release) and cached in the npz.
- Onset function: octave-band spectral flux, hop 5 ms.
- Beat grid: tempo estimate + verified beats. A beat exists only where a real onset peak supports it, and the period must
  hold across windows (onset autocorrelation vs a shuffled null). Output: beat times, confidence, bpm map.

## CLI (`py -3 beatrig.py ...`)
- `analyze <rig>`: build or refresh the cache and print a summary (bpm, beats, duration).
- `notes init|snap|show <rig> ...`
- `bake <rig> [--out bake.json]`: evaluate and write the bake. Prints a per-output min/max/mean and the key counts.
- `check <rig>`: validate the rig (unknown ops/params, cycles, channel mismatches vs actor counts, rule 1/2 violations).
- `serve <rig> [--port 4700]`: preview page (localhost only).

## Python API (used by the server and tests)
`beatrig.load_rig(path) -> Rig`, `beatrig.analyze(rig) -> Analysis`, `beatrig.evaluate(rig, analysis, notes) -> dict[node_id, Signal]`,
`beatrig.bake(rig, ...) -> dict` (the bake.json structure), `beatrig.load_notes/save_notes`.

## bake.json
```jsonc
{ "version": 1, "fps": 30, "frames": 900, "audio": "...", "rig_hash": "sha256...",
  "outputs": [ { "id": "lights", "target": { ... as in rig ... }, "min": 500, "max": 20000,
                 "channels": [ { "actor": "Light_0", "values": [ ... per frame ... ],
                                 "keys": [ [frame, value], ... ] } ] } ] }
```
`values` are final (already remapped to min..max). `keys` are a simplified set from the RDP pass over the values. The
tolerance is relative to max-min. The first and last frames are always kept, and every trigger hit frame is kept.

## Preview server (`serve`, http://127.0.0.1:4700)
- `GET /` page. `GET /api/state` returns the rig, notes, analysis summary (waveform peaks at about 200 px/s, band previews, beats, bpm map),
  and the bake (values downsampled to ≤ 2000 points/channel plus full key lists).
- `GET /api/audio` streams the wav. `POST /api/rig` (full rig JSON) validates, re-bakes and returns the new bake (or errors).
  `POST /api/notes` saves notes, re-bakes and returns the result. `POST /api/save` writes rig.json/notes.json to disk (a backup `.bak` first).
- The page shows:
  - the waveform plus a beat grid
  - note lanes per track (click to add, drag to move, drag vertically for velocity, Delete removes, snap toggle)
  - a curve view per output channel
  - a schematic preview: lights as a ring of dots whose brightness follows their channel, MPC params as bars
  - an audio player with a playhead synced to all views
  - a param panel generated from the rig: a slider for every numeric node/output param, with re-bake on release
- No framework build step: plain HTML/JS/CSS served by the Python server (stdlib `http.server`), so it runs anywhere.

## Unreal applier (`ue/beatrig_apply.py`, runs inside the editor; NOT run in v0)
Reads bake.json and writes keys into a Level Sequence. Everything goes on tracks tagged `beatrig:<output id>`, so `undo` removes
exactly what it wrote. It covers MPC scalar/vector params (MovieScene MPC track; **keys take TICK time, 24000/s, not frames**:
), light intensity/colour, material scalar/vector params on actors, Niagara user params, and transforms
(additive). Steps: `apply <seq> <bake>`, `undo <seq> [output]`, `check <seq> <bake>` (reads keys back and compares).
